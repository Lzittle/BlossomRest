# 花托 · Blossom Rest

> 常驻桌面角落的「中转站」：文件、文件夹、文字、图片先随手放进来，需要时再复制或拖到微信、AI 会话、资源管理器。

中文发布名「花托」，英文名 **Blossom Rest**，代码内部代号 `TransitShelf`。
命名由来：花托是花朵基部承托花瓣的结构，草莓红色的那部分就是膨大的花托。

## 这是什么

Windows 桌面上一个常驻置顶的小浮窗。把散落在微信接收目录、下载目录、项目目录里的文件，
以及随手复制的多段文字和图片，先暂存到这个小框里，再拿去用。

**核心是「引用式暂存」**：文件和文件夹条目只记录路径，不复制内容。架子上始终是系统里的那一份原件，
零拷贝、不占额外空间；删除条目也不会动你的原始文件。

## 已经能做什么

**浮窗**

- 常驻置顶；被其他置顶窗口压住后会自动抢回顶层（实测 5 秒内抢回）
- 不抢焦点、不进 Alt+Tab，展开收起不影响你正在输入的窗口与输入法状态
- 三种展开方式：点击胶囊、拖拽经过热区、鼠标悬浮 300 毫秒
- 贴边收起成胶囊；`Ctrl+Alt+D` 全局快捷键唤出或收起

**收进来**

- 拖入文件、文件夹（均支持多选）、文字、图片
- `Ctrl+Alt+C`、面板「收录」按钮或托盘菜单一键收录剪贴板内容（文件 &gt; 文字 &gt; 图片）
- 面板「添加」按钮与托盘菜单手动挑选文件
- 目录监听自动进架：下载目录与微信接收目录，**默认关闭**，需要时在托盘菜单里打开
- 文件名乱码修复（GBK 名称还原成可读中文）

**拿出去**

- 单击复制：文件走绝对路径列表，文字走纯文本，图片同时提供位图与缓存 PNG
- 多选模式复制路径清单：换行分隔、按列表顺序，贴进 AI 会话即可直接当作引用地址
- 拖出到微信、资源管理器、浏览器等目标应用
- 文件夹单击打开，文件双击打开；右键可定位到资源管理器或复制完整路径

**条目的保存**

- 重启后条目仍在（本地 `state.json`），失效条目会标记而不是报错
- 9 条上限、24 小时过期清理
- 无源图片（截图、网页直接复制得到的位图）落成缓存 PNG，退出时清理，强制结束进程后重启也能清掉孤儿缓存

**界面**

- 两套可切换配色：Catppuccin Frappe（深色，默认）/ Rosé Pine Dawn（浅色），托盘「配色」菜单切换
- 图标与空状态插画全部是自绘 XAML 矢量，不依赖图标字体与 emoji
- 不透明实色面板。亚克力背景会让配色饱和度发灰，已关闭；实现保留在 `WindowMaterial`，将来可做成可选材质

**隐私与边界**

- 无网络、无遥测、无账号体系，不联网也不上报
- 不做微信窗口自动化：不注入、不驱动第三方客户端、不自动发送
- 删除条目、清空、过期清理都不会删除你的原始文件

## 环境要求

- Windows 10 1809 及以上，或 Windows 11（64 位）
- .NET 8 SDK（仅构建需要；只想运行则装 .NET 8 桌面运行时）
- 本机 SDK 装在 `%LOCALAPPDATA%\Microsoft\dotnet`，没有写进系统 PATH，因此构建统一走仓库里的包装脚本

## 构建与运行

```powershell
.\scripts\dev.ps1 build      # 构建
.\scripts\run.ps1            # 启动
.\scripts\dev.ps1 test       # 单元测试
```

> 脚本必须保持纯 ASCII：Windows PowerShell 5.1 会把无 BOM 的 UTF-8 脚本按 GBK 读取，中文注释会导致解析失败。

自动验收脚本（需要先构建），覆盖三处必须依赖真实系统交互的功能：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\verify-collect.ps1      # 剪贴板收藏
powershell -ExecutionPolicy Bypass -File .\scripts\verify-watch.ps1        # 目录监听
powershell -ExecutionPolicy Bypass -File .\scripts\verify-multiselect.ps1  # 多选路径清单
```

## 设计红线

下面这些是经过调研与实测确认的边界。若认为需要调整，要先说明理由、更新文档，并获得明确确认。

| 编号 | 红线 | 原因 |
| --- | --- | --- |
| R1 | 技术栈为 C# + WPF（.NET），不得引入 Electron / Tauri / 网页壳作为主界面 | Web 壳的出站拖拽只支持文件路径，文字与图片拖不出去 |
| R2 | 不得引入 Vue / React 等 Web 前端框架做主界面 | 同上 |
| R3 | 引用式暂存：文件与文件夹条目只存路径，不复制内容 | 零拷贝是产品核心价值 |
| R4 | 删除条目绝不删除用户原始文件 | 数据安全底线 |
| R5 | 不做微信窗口自动化 | 脆弱、有账号风险、违反平台约束 |
| R6 | 自动采集默认关闭（目录监听、剪贴板监听） | 隐私优先，用户显式开启才生效 |
| R7 | 无网络、无遥测、无账号体系 | 本地工具，缩小风险面 |
| R8 | 无源图片必须落缓存 PNG，不长期持有位图 | 剪贴板位图会被覆盖，位图常驻内存开销大 |
| R9 | 不引入新的重量级依赖 | 保持体积与启动速度 |

## 调研结论（速览）

1. **引用式暂存（零拷贝）**：架子里只存路径指针，文件在系统里始终只有一份。
2. **复制粘贴为主通道、拖拽为可选增强**：粘贴走系统通用通道，兼容性最好。
3. 核心依赖 Windows 原生拖放能力，因此必须用原生技术栈；Electron 的拖拽接口只能拖出文件路径，拖不出文字和图片。
4. 市面上没有可直接使用的成熟同类产品，Windows 侧开源实现都是低星雏形，所以选择自研。
5. 定位包含两层：自动过期的**临时区** + 长期保留的**工作区**（工作区尚未实现）。
6. 明确不做微信窗口自动化，微信侧只保留「复制后自己粘贴」。
7. 自动化采集全部默认关闭，默认只处理用户自己放进去的东西。
